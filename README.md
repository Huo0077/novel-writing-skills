# 小说创作 Skills

**让 AI 协助你写长篇，同时把故事的决定权留在你手里。**

这是一套面向小说创作者的 AI 协作技能组。它把设定整理、剧情规划、正文写作、文段回审和修订衔接起来，帮助你处理写长篇时常见的上下文遗忘、角色漂移、重复表达、节奏失控和过于明显的伏笔。

你不需要记住 31 个技能名。通过一个入口 `novel-router`，用自然语言说明当前任务即可。

[下载 v1.1](https://github.com/Huo0077/novel-writing-skills/releases/tag/v1.1) · [完整使用指南](docs/novel-skills/skills组使用指南.md) · [快速开始](小说skills-快速开始.md) · [历史版本](https://github.com/Huo0077/novel-writing-skills/releases)

> 这不是独立运行的小说生成软件，而是一套供**能读取、编辑本地文件，并遵循技能指令的 AI 助手**使用的流程与工具。普通聊天窗口不会因为下载了文件就自动具备这些能力。

## 它能帮你做什么？

| 写作中遇到的问题 | 技能组提供的处理方式 |
|---|---|
| 写到后面忘了人物受伤、物品去向或旧承诺 | 把世界规则、人物状态、时间线和关键事件记录在作品档案中；写前读取相关状态，写后提取实际变化 |
| 配角越来越像同一个人，对白没有辨识度 | 从关注点、措辞策略、回避方式和压力反应区分人物，而不只给每人加一个口头禅 |
| “微微一怔”、同一种句式或标点反复出现 | 统计重复位置，结合语境判读，再给改写候选；保留有意的主题意象、角色口吻和回环 |
| 一章推进太多，真相过早揭露，情绪突然跳变 | 分开章节与场景目标，限制信息释放，检查情绪积累、转折依据和高潮余波 |
| 伏笔一眼就能看穿，反转只靠临时补设定 | 让线索先服务当前场景，建立有依据的竞争解释，再检查揭示前证据与回看意义 |
| 改了一段，后文状态和伏笔跟着乱了 | 区分纯措辞与事实改动，列出下游影响，保留旧版本，重大变更先确认 |

这些机制用于**降低风险、让问题可追踪**，不保证 AI 永不遗忘，也不保证每个反转都会令人惊艳。

## 开始使用：三步

### 1. 下载并打开完整项目

到 [v1.1 Release](https://github.com/Huo0077/novel-writing-skills/releases/tag/v1.1) 下载 `novel-writing-skills-v1.1.zip`，解压到一个**空的新目录**，然后让你的 AI 助手打开该目录。

保留完整目录，尤其是 `.codex/` 和 `.novel/`；部分文件管理器会隐藏它们。不要只复制一个 `SKILL.md`，因为技能之间共用协议与模板。

已有小说不要直接用 ZIP 覆盖。可以先在新目录使用，再让助手按只增不覆盖的初始化流程接入你的原稿；具体见[使用指南](docs/novel-skills/skills组使用指南.md)。

### 2. 告诉助手使用总控入口

复制下面这段话：

```text
请读取当前项目的 .codex/skills/novel-router/SKILL.md，并按它处理我的小说任务。

我想开始一部新小说。先了解我的创作目标和已有想法，一次只问一个关键问题。
缺少信息时，给我 2–3 个不同方向及其影响，也允许我自己补充或暂时不决定。
不要把你推荐的方案直接当成我的设定。
```

如果助手找不到文件，提供你解压目录中 `novel-router/SKILL.md` 的**完整路径**。能找到文件并不等于应用会自动加载技能，必要时要求它先阅读指令再开始。

已经有原稿？把最后一章、相关设定或当前问题提供给助手，明确哪些已经确定、哪些仍是草稿；不必一次整理整部小说百科。

### 3. 选择你希望的协作方式

| 模式 | 适合你希望…… | AI 的工作方式 |
|---|---|---|
| **作者助手** | 自己决定剧情，只让 AI 整理、扩写和检查 | 以执行你的意图和提出建议为主 |
| **协同作者** | 与 AI 一起讨论人物选择、剧情和伏笔 | 可以主动提供候选方向，并说明后果 |
| **半自动长篇** | 沿已确认方向分批推进，减少反复操作 | 在批准范围内规划和写作，遇重大变更暂停 |

模式可以按项目或任务切换。**半自动不等于无监督**：改变世界规则、核心动机、关键事件结果或完整揭示等高风险操作仍需要你确认。

## 直接这样提出任务

使用时先让助手读取总控入口，之后说明任务即可，不必自己编排技能链。

### 续写当前场景

```text
继续这一场。先核对人物伤势、物品、关系和知识边界，列出当前目标与不能揭示的内容。
如果关键资料缺失，先问我；确认范围后再写。
达到本场退出条件就停，回审实际发生的变化，不自动推进到下一章。
```

### 检查前后矛盾

```text
检查这段正文与已有设定是否矛盾。
把明确矛盾、可能问题和资料不足分开，给出正文与档案来源。
先提供修复方向，不改我的正史。
```

### 减少重复表达

```text
检查这章高频词组、句式、动作和标点。
先区分有效、可疑、无效重复，保留主题意象和角色声音。
对需要改的地方给语境化候选，说明是否新增动作或改变原意，不机械替换同义词。
```

### 改进过于明显的伏笔

```text
这条伏笔太容易看出来。检查它是否有当前场景中的自然用途、是否被旁白过度强调。
给出有证据支持的竞争解释，并检查揭示后能否重新解释旧内容。
如果真相或场景用途还没确定，先向我提问，不自行造新秘密。
```

### 结束本次写作

```text
保存当前进度：哪些事实已确认、哪些暂定、哪些等我决定。
记录未兑现的承诺、待推进伏笔、下一步安全任务和不能提前揭示的内容。
```

## 你始终拥有决定权

**缺信息时先问，不默认替你选。** 助手先查看已有资料，再询问当前阻塞点；选项会说明差异与影响，你可以选择、自定义或暂缓。只回答一部分，就只确认那一部分。

**草稿不是自动正史。** 系统区分已确认事实、暂定内容、候选提案和草稿。计划“这一章要拿到账本”，不意味着正文已经实际完成；写后会回审结果。

**按影响分级确认。**

- 低风险：可记录为暂定状态。
- 中风险：在任务或阶段结束时汇总确认。
- 高风险：先暂停，说明影响并询问。

**修订保留原稿。** 改写另存版本；如果新增动作、承诺、线索或知情状态，就作为事实变化检查，而不是假装只是语言润色。

## 写作资料放在哪里？

```text
.codex/skills/   技能指令与工具；novel-router 是统一入口
.novel/
  canon/        世界、人物、时间线、关键事件、伏笔与信息边界
  planning/     总纲、章节与场景计划
  drafts/       正文草稿与历史版本
  reviews/      回审、表达、连续性与节奏检查
  proposals/    等待决定的建议、状态变更与澄清问题
  checkpoints/  可恢复的写作进度
  schemas/      共用协议
  templates/    记录模板
```

`canon/` 是档案位置，不代表里面每条候选都已确认。状态与来源仍要明确记录。

测试目录中的人物和故事只用于验收，**不是你的作品设定**。公开下载包是空白项目种子，不携带创作者真实作品数据。

> **保护你的原稿与秘密：** 本仓库是公开的。不要将填写了真实作品内容的 `.novel/`、正文、作者真相或私人提案直接提交到公开仓库。使用本地目录或你自己的私有工作区，并自行做好备份。

## 工具与检查（可选）

日常使用以助手读取技能并执行流程为主。表达统计、材料准备、完整验收和迁移工具需要 Python；运行整组验收还需要 PyYAML。

在项目根目录执行：

```powershell
python -m pip install "PyYAML>=6.0,<7.0"
python .codex/skills/novel-router/scripts/suite.py validate --tests
```

初始化新目录先预览，确认后才新增文件：

```powershell
python .codex/skills/novel-router/scripts/suite.py bootstrap 新作品目录
python .codex/skills/novel-router/scripts/suite.py bootstrap 新作品目录 --apply
```

初始化工具不会覆盖已有文件；但保留旧文件不等于版本已自动合并，已有作品仍须检查兼容性。ZIP 解压器也不受这条规则保护，因此不要直接解压覆盖旧项目。

## 已验证什么，还没验证什么？

v1.1 已修复六类状态校验漏洞，并接入全组澄清协议。公开 Release 重新下载后的验收结果为：**122 个案例，121 通过、1 项因软链接权限限制跳过、0 失败**。

这些检查验证格式、工具和资料交接，**不是**独立模型对话、真人首次阅读或长篇文学质量实验。仍需关注：

- 长篇中是否持续正确读取和更新状态，要靠实际作品检验。
- 重复表达统计不等于中文分词或“AI 作者鉴定”。
- 知道真相的会话不能充当独立读者；首次阅读测试需要没见过答案的新上下文或真人。
- 公开信息包与作者笔记分离是流程约束，不是技术访问隔离。
- 未承诺全局安装、界面自动发现或后台自动多代理写作。

完整证据见[复核报告](docs/novel-skills/GitHub-v1.1-复核报告.md)和[验证摘要](docs/novel-skills/verification/v1.1-public-verification.json)。历史 v1.0 保留在 Releases 中，存在已知校验缺陷，建议使用 v1.1。

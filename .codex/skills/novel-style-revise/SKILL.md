# 有范围的风格修订

## 输入
原稿/版本、审查报告、候选、创作者批准范围、信息/声音约束、保护项。使用 .novel/schemas/audit-revision-contract.md。

## 执行
1. 检查修改范围、候选是否批准、哪些原句必须保留。缺授权只给候选不覆盖正文。
2. 先应用词句/信息顺序层的最小修改；新增动作、物品、感情或承诺不作为纯措辞自动批准。
3. 结合邻段调整衔接，不把各处候选生硬拼在一起；不为达到“词汇多样”牺牲指代、朴素语言或节奏。
4. 另存DRAFT新版本，保留原稿及修订来源。正文和说明分开。
5. 逐项对照meaning_constraints、保护意象、人物声音和揭示程度；检测因改写增加/减少的事实。
6. 可重跑统计对比，但计数减少不是文学质量结论，有效重复可保持高频。
7. 执行novel-segment-review与必要continuity/causality核查，new_facts交 novel-canon 分级。事实改变交impact-review查下游。
8. 保存revision_report和checkpoint。未批准变化标creator_pending，不能直接算正史修好了。

## 输出
新DRAFT、实际应用/未应用清单、语义对照、新事实、保护项、统计变化、回审与下游影响引用、未决决定。

## 权限
不批量机械替换所有同词，不自动删伏笔。保持原始文件；未保存时明确文本交付而非捏造文件引用。

## 缺信息与用户选项
遵守 `.novel/schemas/clarification-contract.md`：先查已有答案，一次问一个当前关键缺口，给2–3个不同方向及后果，并允许自定义或暂不决定。未知/冲突/授权缺失不能靠猜测补正史；仅暂停依赖步骤。用户答复按实际来源和明确范围记录，高风险许可不足仍交novel-canon暂停。

# 缺信息、选项与用户补充协议 v1.0

本协议供作者协作任务使用，统一适用于31个技能。reader独立首次阅读路线不加载作者档案/本协议的作者示例，只中性询问缺失的阅读材料或范围，不给答案候选、不提示秘密。

## 何时问

1. 先查看获准的相关资料和用户已给答案，找不到/互相冲突时说明missing_information和两侧source_ref；不重复问已有确定项。
2. 信息关系到当前动作资格、人物选择、世界规则、时间、因果、知情来源、伏笔真相、风格意图或批准范围时问。机器报非法格式时先说明缺口，不能替用户编合格事实。
3. 不阻塞的远期细节保持unknown，记录待补；普通可逆措辞可在授权范围内处理。不要要求完整世界百科才能检查一段。
4. 一次问一个当前关键问题。多项缺口可以给待办摘要，但本轮只展开当前决定，不同时发十道问卷。

## 问题结构

```yaml
question_id: Q-001
missing_information: "当前必须补齐的内容"
blocking_scope: "哪些步骤需要这项信息"
source_ref:
  - "已查看的档案或用户材料"
question: "一个具体问题"
options:
  - id: A
    description: "第一种不同方向"
    tradeoff: "它对当前情节/规则/人物/读者信息的影响"
  - id: B
    description: "第二种不同方向"
    tradeoff: "它的不同影响"
custom_answer: true
undecided: true
selected_option: null
user_answer: null
confirmation_scope: []
answer_status: unanswered
```

提供2–3个真正不同的可选方向，说明简短后果和新增事实。只是建议，不替用户默认选，不用措辞诱使用户同意AI。涉及风格/解释/剧情时允许自定义答复或暂不决定。
能推荐时解释理由，但推荐不等于批准；高风险不能设置超时默认。没有依据形成选项时不编假事实，选项改为处理方向（提供原稿、先保留未知、另选作者方案）。
选项里不得偷带重要秘密作为已确认事实。未知钥匙归还，不把“何青就是凶手”作为有根据的解释。

## 用户答复

- 选A/B/C：复述选中项、影响与confirmation_scope，记录user_answer和实际答复来源。
- custom_answer：保留用户自己的设定，不硬套最接近选项；若仍有阻塞只追问剩下的一点。
- 部分答复：只更新回答的部分，其余still_unknown；绝不当全部选项一起批准。
- 暂不决定/undecided：依赖步骤blocked，保留未知，可做不依赖它的统计/诊断/资料整理。
- 含糊/互相矛盾：显示问题与影响，确认一个关键点，不凭概率猜用户意图。

问题和答复可单独存 `.novel/proposals/questions/Q-*.yaml`，不是状态变更提案或自动正史。来源不能填虚构的用户确认。未收到答复保持null/unanswered。
复述核对不必变成每次重复确认：答复已明确批准当前选项及其后果，可引用该决定直接继续该范围。

## 与正史及风险的关系

用户补信息→核与现有CANON是否冲突→必要时按status-change.md生成before/after与影响→novel-canon按风险处理→更新对应档案和checkpoint。
回答“选这个表达方向”不等于批准新世界规则、角色死亡或核心揭示。高风险问题须说明重大后果和具体许可范围；原答复不足以授权时继续paused。
用户明确选择具有清楚后果说明的高风险操作时可作为该次具体许可，不强迫无限重复问；保留确认来源、旧事实与下游同步。
允许用户更改旧设定，但不能静默覆盖；若有冲突先说明影响与版本链。未知真实答案不能因语言改写而被确定。

## 不同任务的提问重点

- 初始化：当前创作目标/模式/最小故事起点，不同时强要名字、篇幅、结局、所有人物。
- 连续性：以冲突为题，提供“保留旧事实改正文 / 改事实并同步 / 先核材料”等处理选项。
- 伏笔：先问隐藏事实是否已定与当前场景用途；真相未知，不自行造惊天答案。
- 表达：问重复是不是保护性意象/口吻；可选保持、局部减少、调整位置，不把全部同词替换作为默认。
- 自动推进：授权范围/高风险缺失无论何种mode均暂停，不能靠半自动模式默认选。
- reader：只确认阅读范围/缺失片段，不能向测试者问作者真相；答案污染时退出独立标签。

## 验证边界

提问格式与演练产物可静态验收，但“模型一定在所有缺口发问”不是工具强保证，需要真实任务与用户反馈。用户来源非空也不证明身份或真实性；结构验证不等于决策认证。
